How ForgeOS boots, how to build it from source, and how the package system works.

Architecture

ForgeOS boots without GRUB or any third-party bootloader. The BIOS loads a 512-byte boot sector at address 0x7C00, which:

  1. Uses BIOS INT 13h extended reads to load the kernel image from disk into memory.
  2. Enables the A20 line and builds a minimal 32-bit GDT.
  3. Sets CR0's protection bit and far-jumps into 32-bit protected mode.

The kernel then takes over its own transition into 64-bit long mode: it builds page tables mapping the first gigabyte of memory, sets CR4's PAE bit, enables long mode in the EFER MSR, and enables paging via CR0. Once in 64-bit mode, it jumps into C code.

Layout

boot/
  stage1.asm    16-bit boot sector, loads kernel, enters protected mode
  kentry.asm    32-bit to 64-bit long mode transition
kernel/
  kernel.c      shell + command dispatcher
  vga.c/.h      VGA text-mode driver
  keyboard.c/.h PS/2 keyboard driver (polling, scancode set 1)
  kstring.c/.h  freestanding string helpers (no libc)
  ramfs.c/.h    in-memory filesystem
  link.ld       linker script, loads kernel at 0x8000
build/
  build.sh      assembles, compiles, links, masters the ISO

Building from source

You'll need nasm, gcc (with standard binutils), and xorriso. All three can be built from source if your system doesn't have them packaged.

git clone https://github.com/forge0s/forge-packages.git
cd forgeos
bash build/build.sh

This produces build/forgeos.iso. Test it with:

qemu-system-x86_64 -cdrom build/forgeos.iso

Or flash it to a USB drive and boot real hardware.

Packaging

ForgeOS packages are called fpk files. An .fpk is a plain gzip tarball (the extension is a convention, not a distinct format) containing:

manifest.json
src/       source files
bin/       precompiled objects, if any

A minimal manifest:

{
  "name": "fastfetch",
  "version": "1.0.0",
  "description": "...",
  "author": "...",
  "type": "kernel-builtin",
  "files": ["src/fastfetch.c", "src/fastfetch.h"]
}

Why "kernel-builtin" packages exist

ForgeOS doesn't have a userspace, processes, or an ELF loader yet — every command runs inside the kernel itself. Until that changes, a package can't ship a standalone executable; instead it ships source that gets compiled directly into the kernel and wired into the shell's command dispatcher. It's not elegant, but it's honest about where the OS currently is.

The repo index

All available packages are listed in a single packages.json at the root of the package repo:

{
  "packages": [
    {
      "name": "fastfetch",
      "version": "1.0.0",
      "url": "https://forge0s.github.io/forge-packages/packages/fastfetch.tar.gz",
      "sha256": "4b1d15a7e808c7ecdba9901abadfe6963f05c6150bf886b47942e9b70c8e7724"
    }
  ]
}

fpkg install <name> is designed to fetch this file, find the matching entry, download the tarball, verify its checksum, and extract it — once ForgeOS has a network stack. Today it's a stub that explains this plan when you run it.

Publishing a package

  1. Build your .fpk tarball with a manifest.json inside.
  2. Commit it to the packages/ directory of the package repo.
  3. Add an entry to packages.json with its download URL and sha256 checksum.
  4. Push. GitHub Pages serves it within a minute — no build step, no approval queue.

Hosting a package repo for free

The package repo is entirely static files, which means GitHub Pages hosts it for free with no domain purchase required:

  1. Create a public GitHub repo, e.g. forge-packages.
  2. Add packages.json at the root and your .fpk files under packages/.
  3. In the repo's Settings → Pages, set the source to the main branch, root folder.
  4. GitHub serves it at https://<username>.github.io/<repo>/ — permanent and free.

For larger binaries, attach them to a GitHub Release instead of committing them directly, and point packages.json at the release URL.

Roadmap

In the order they unlock the most:

  1. Boot-test on real hardware and in QEMU/VirtualBox.
  2. A disk driver (ATA/IDE PIO) plus a real filesystem, so state survives a reboot.
  3. A NIC driver (RTL8139 is the usual first target) and a minimal TCP/IP stack.
  4. Wire fpkg install to actually fetch from a live packages.json.
  5. A userspace and ELF loader, so packages stop needing to be kernel-builtins.
  6. A graphics-mode framebuffer, then a compositor, then a desktop environment.
